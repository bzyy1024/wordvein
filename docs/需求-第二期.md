# 需求-第二期：收藏、访客统计与管理端

> 状态：**第一批已交付并可运行**（收藏单词 + 匿名访客 + 管理端）
> 一期范围：查词与构词拆解闭环；二期补上"留住用户"与"看得见运营数据"两块。

---

## 一、本期目标

1. 让用户能**留下**查过的词（收藏），下次直接回看
2. 让运营**看得见**站点在发生什么：多少人、查了多少词、哪些词最受欢迎
3. 全程不引入账号体系，不收集手机号 / 邮箱等个人信息

---

## 二、已交付功能

### 1. 收藏单词

| 项 | 说明 |
| --- | --- |
| 入口 | 单词详情页标题下方「☆ 收藏 / ★ 已收藏」 |
| 收藏夹 | `/favorites`，按收藏时间倒序，可单条取消 |
| 存储 | 服务端 `favorites` 表，挂在浏览器匿名 uuid 上 |
| 上限 | 列表接口默认取 200 条 |
| 失败反馈 | 词不在库中提示"词库中没有这个单词"；网络失败提示重试 |

不做登录即可收藏，代价是**换设备或清理浏览器数据后收藏不跟随**。
这是"先验证需求真伪"的取舍：等收藏功能被真实使用后，再评估是否值得做账号体系。

### 2. 匿名访客统计

| 项 | 说明 |
| --- | --- |
| 标识 | 首次访问生成 uuid 存 `localStorage`（key `ew_uid`） |
| 上报 | 会话开始上报 `visit`；打开单词页上报 `query` |
| 记录内容 | uuid、首次/最近活跃时间、累计查词次数、浏览器 UA |
| **不记录** | IP、手机号、邮箱、具体搜索内容 |

隐私模式下 `localStorage` 不可用时直接跳过上报，不影响查词。

### 3. 管理端

| 项 | 说明 |
| --- | --- |
| 地址 | 独立端口 `ADMIN_PORT`（默认 8311），与站点端口隔离 |
| 入口 | `/admin`，未登录跳转 `/admin/login` |
| 登录 | 环境变量 `ADMIN_PASSWORD` 口令；会话 12 小时，httpOnly Cookie |
| 概览页 | 词库规模（单词 / 词素 / 义项 / 拆解关系）、收藏总数、访客数、今日与近 7 日活跃、被收藏最多的词、最近导入批次 |
| 用户页 | 访客列表：uuid、查词数、收藏数、首次访问、最近活跃，20 条分页 |

管理容器带 `ADMIN_MODE=1`，访问非 `/admin` 路径会被收拢到管理端；
建议该端口只对本机或内网开放。

## 三、数据模型

```sql
users (
  id            text PRIMARY KEY,   -- 浏览器生成的匿名 uuid
  created_at    timestamptz,
  last_seen_at  timestamptz,
  query_count   integer DEFAULT 0,  -- 累计查词次数
  ua            text,               -- 浏览器标识，仅排障用
  first_ref     text
);

favorites (
  user_id    text REFERENCES users(id) ON DELETE CASCADE,
  word_id    bigint REFERENCES words(id) ON DELETE CASCADE,
  created_at timestamptz,
  note       text,
  PRIMARY KEY (user_id, word_id)
);
```

两张表都在 `docs/schema.sql`（权威定义）与 `src/db/schema.ts`（Drizzle 镜像）中，
由 `pnpm db:check` 校验两边一致；`pnpm db:init` 幂等建表。

---

## 四、接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/track` | `{ uid, event: 'visit' \| 'query', ref? }`，upsert 访客并按需累加查词数 |
| GET | `/api/favorite?uid=` | 收藏列表（单词、音标、串讲、收藏时间） |
| POST | `/api/favorite` | `{ uid, word }` 加入收藏；词不存在返回 404 |
| DELETE | `/api/favorite` | `{ uid, word }` 取消收藏 |

## 五、验收记录

| 场景 | 结果 |
| --- | --- |
| `POST /api/track` | 200，写入 `users` |
| 收藏 → 列表 → 取消 → 列表 | 依次返回 `ok` / 1 条 / `ok` / 0 条 |
| 未登录访问 `/admin`、`/admin/users` | 均返回登录页，无数据泄漏 |
| 带会话 Cookie 访问 `/admin`、`/admin/users` | 返回概览页与访客列表 |
| `pnpm db:check` | SQL 与 TS 定义 10 张表完全一致 |
| `tsc --noEmit` / `next build` | 通过 |

## 六、已知限制

1. **跨设备不同步**：收藏挂在浏览器 uuid 上，换设备即丢失
2. **uid 可伪造**：无签名校验，知道他人 uuid 即可读写其收藏；收藏内容非敏感，暂接受
3. **无回收站**：取消收藏直接删除
4. **统计粒度粗**：只有累计查词数与最近活跃，没有时间序列

## 七、后续候选（未做，按优先级）

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| P1 | 历史记录 | 记录查过的词，与收藏区分，可清空 |
| P1 | 词单导出 | 收藏导出为 Anki / CSV，或生成分享链接 |
| P2 | 生词本与复习 | 标记「已掌握 / 待复习」，按记忆曲线推送 |
| P2 | 学习统计 | 今日查词数、连续签到、掌握进度看板 |
| P3 | 账号体系 | 邮箱或第三方登录，收藏跨设备同步；届时把 uid 换成 user_id 即可 |

做账号体系时，`favorites.user_id` 与 `users.id` 仍是同一套主键语义，
只需把 uuid 换成真实用户 ID，UI 层不用重写。
